# مسار التسويق وإدارة الإعلانات

نظام متابعة المصروفات التسويقية والفواتير وقياس أداء القنوات الإعلانية — واجهة عربية كاملة (RTL).

**🔗 الرابط المباشر: https://afnadsana.github.io/afnad-sana/**

> واجهة ثابتة (HTML + CSS + JavaScript بدون خطوة بناء) متصلة بقاعدة بيانات Supabase.
> البيانات مشتركة بين كل أعضاء المنشأة وتتزامن على كل الأجهزة.

---

| | |
|---|---|

| **الإدخالات اليومية** | تسجيل الصرف والمبيعات يوماً بيوم لكل قناة، مع إضافة وتعديل وحذف |

## المؤشرات المحسوبة

| المؤشر | المعادلة |
|---|---|
| ROAS | المبيعات ÷ الصرف التسويقي |
| متوسط تكلفة الطلب | الصرف التسويقي ÷ عدد الطلبات |
| نسبة التسويق | (الصرف التسويقي ÷ المبيعات) × 100 |
| الربح | المبيعات − الصرف التسويقي − تكلفة البضاعة |

## الفواتير والحسابات

قسم مستقل يعمل كـ**دفتر للحساب البنكي**: تُدرج فيه كل مبلغ تحرّك فعلاً، فيحسب لك الرصيد.

**كل فاتورة تحمل:** التاريخ · النوع (وارد/صادر) · المبلغ · الجهة · رقم الفاتورة ·
التصنيف · طريقة الدفع · الحالة · المنشأة · ملاحظات.

### كيف يُحسب الرصيد

```
الرصيد الحالي   = الرصيد الافتتاحي + كل الوارد المسدّد − كل المنصرف المسدّد
الرصيد المتوقع  = الرصيد الحالي + المعلّق الوارد − المعلّق الصادر
```

- **الرصيد تراكمي** ولا يتأثر بفلتر الفترة — لأن رصيد البنك لا «يبدأ من جديد» كل شهر.
  أما بطاقات «وارد الفترة / منصرف الفترة / صافي الفترة» فتتبع الفترة المختارة.
- **الفاتورة المعلّقة لا تؤثر على الرصيد** حتى تُسدَّد؛ تظهر في «الرصيد المتوقع» فقط،
  ولها زر «تسديد» ينقلها للرصيد الفعلي.
- **ابدأ بضبط الرصيد الافتتاحي** (زر «الرصيد الافتتاحي») = ما لديك في الحساب قبل تسجيل أي فاتورة.

### مطابقة الصرف التسويقي

الصرف المسجّل في «مسار التسويق» **لا يُخصم تلقائياً** من الرصيد البنكي — لتفادي الازدواج
في الحساب. لوحة «مطابقة الصرف التسويقي» تعرض الفارق بين ما سُجّل هناك وبين فواتير
تصنيف «تسويق»، ليظهر لك ما لم يُدرج بعد كفاتورة.

## البدء

1. افتح **https://afnadsana.github.io/afnad-sana/**
2. أنشئ حسابك وأكّد بريدك من رسالة التأكيد
3. من **الإعدادات** اضبط **الرصيد الافتتاحي** لحسابك البنكي — كل حسابات الخزينة تُبنى عليه
4. شارك الرابط مع فريقك، ثم أضفهم من **الفريق والصلاحيات**

```bash

```

يتصل بنفس قاعدة البيانات، فأضف `http://localhost:8777` إلى
Redirect URLs في إعدادات Supabase.

## الحسابات والصلاحيات

كل مستخدم ينشئ حسابه بنفسه من الرابط، ثم يضيفه المالك أو المدير من صفحة **الفريق والصلاحيات**.

| الصلاحية | ما يستطيع فعله |
|---|---|
| **مالك** | كل شيء، بما فيه إدارة الفريق |
| **مدير** | إدخال وتعديل وحذف + دعوة أعضاء |
| **عضو** | إدخال وتعديل وحذف البيانات |
| **مشاهد فقط** | الاطلاع على التقارير دون أي تعديل |

أول من يسجّل يصبح **مالك** المنشأة تلقائياً، وتُنشأ له منشأة وقنوات افتراضية.

المستخدم الذي يسجّل ولم يُدعَ بعد لا يرى شيئاً من بياناتك — تُنشأ له منشأة فارغة خاصة به.

## أين تُحفظ البيانات؟

في قاعدة بيانات **Postgres على Supabase** (منطقة فرانكفورت)، مع نسخ احتياطي تلقائي.

الحماية مبنية على **Row Level Security**: كل جدول محميّ بسياسات تمنع قراءة أو كتابة
أي صف خارج منشأة المستخدم — حتى لو استُخدم المفتاح العلني مباشرةً.

تم التحقق عملياً: الوصول بدون تسجيل دخول يعيد **صفر صفوف** من كل الجداول،
واستدعاءات `bootstrap_org` و`invite_member` ومحاولات الإدخال **محجوبة** (خطأ 42501).

### عن المفتاح في `config.js`

مفتاح `anon / publishable` **مصمَّم ليكون علنياً** في كود المتصفح؛ أمان النظام يقوم على
سياسات RLS لا على إخفائه. **لا تضع** مفتاح `service_role` في الكود إطلاقاً — فهو يتجاوز كل الحمايات.

### حدود الخطة المجانية

- رسائل تأكيد البريد محدودة بـ **٢-٣ في الساعة**؛ سجّل فريقك على دفعات أو اربط خدمة SMTP خارجية.
- المشروع يتوقف تلقائياً بعد **أسبوع خمول** ويُستأنف بضغطة زر من لوحة Supabase.

## بنية المشروع

```
index.html              الهيكل وشاشة تسجيل الدخول
assets/css/style.css    التنسيقات (RTL، متجاوب، دعم الطباعة)
assets/js/config.js     رابط ومفتاح Supabase
assets/js/store.js      طبقة البيانات والحسابات والخزينة والصلاحيات
assets/js/charts.js     التنسيق الرقمي والرسوم البيانية (SVG خالص)
assets/js/app.js        الموجّه والشاشات والأحداث وتسجيل الدخول
supabase/schema.sql     الجداول وسياسات RLS ودوال التهيئة والدعوة
```

## ملاحظة على الألوان

ألوان القنوات مأخوذة من لوحة ثابتة تم التحقق منها آلياً: نطاق الإضاءة، حد التشبع،
والفصل البصري بين الألوان المتجاورة لأصحاب عمى الألوان (ΔE 14.8) وللرؤية الطبيعية (ΔE 19.9).
اللون تابع للقناة ولا يتغيّر عند الفرز أو التصفية، وكل صف في الرسوم يحمل اسمه وقيمته نصّاً،
فلا يعتمد التمييز على اللون وحده.
